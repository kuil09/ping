# 프로필과 첫 입장

첫 입장은 닉네임 입력 → 서버 확인 → 입력 필드 숨김 → 가능/불가능 토글 노출 순서다. 기본 상태는 불가능이며 핑이나 이름 적용으로 가능 상태가 되지 않는다.

닉네임 편집은 구성원 목록의 본인 카드에서만 연다. 같은 사용자 목록을 다시 받거나 핑이 도착해도 동일한 DOM 카드/키보드 포커스를 유지한다. 별도의 상단 본인 프로필 행은 없다. 편집 중 수신 핑과 로컬 기록은 계속 동작한다.

닉네임은 NFC 정규화, 공백 정리, 최대 20 Unicode 코드 포인트, 제어/방향제어 문자 제한을 서버와 클라이언트에 동일 적용한다. DOM에는 textContent로 표시한다. 가입 시스템이나 닉네임 유일성은 요구하지 않는다.

## 입력 중 갱신 제한

카운트다운/감쇠를 그리는 250ms 루프는 프로필 폼을 갱신하지 않는다. 연결 상태·사용자 입력·서버 상태·저장 진행 상태가 실제로 바뀔 때만 컨트롤을 갱신한다. 값이 같은 텍스트·속성·프로퍼티는 다시 쓰지 않는다. 특히 textContent에 같은 문자열을 쓰는 것도 기존 버튼 자식 노드를 교체하므로 피한다.

Chromium/WebKit에서 MutationObserver로 유휴 구간 및 상대 핑 수신 시 폼 변경이 없는지 검사하고, 실제 터치 경로로 16회 이름 저장이 각각 한 번 적용되는지 검증한다. 강제 클릭이나 테스트 재시도로 실패를 숨기지 않는다. 테스트 수동 브라우저 컨텍스트에는 별도로 실제 컨텍스트 trace를 기록한다.
